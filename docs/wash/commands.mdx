###### **Options:**

* `-C <PROJECT_PATH>` - Path to the project to run a command against (when outside a project directory)
* `-h`, `--help` - Print help

## Directory Context

The `wash` CLI uses automatic project detection similar to `git` and other GNU tools. This allows you to run `wash` commands from anywhere within your project without specifying the project path.

```shell
~/myproject$ wash dev
~/myproject/wit$ wash build
~/myproject/src$ wash build
```

When you're **outside** a project directory, you can use the `-C` flag to specify the project path. This is useful in CI environments and situations where users can't change directories prior to calling `wash`.

From your home directory, targeting a project in `/tmp`:

```shell
wash -C /tmp/myproject build
```

## `wash config validate`

Check the loaded configuration for hard errors before you run anything against it. Validation covers socket-address syntax, `redis://`/`nats://`/`postgres://` URL schemes, paired TLS cert and key files, WebGPU availability on Windows, non-empty build commands, well-formed WIT registry URLs, and local WIT source paths that actually exist on disk. Remote sources (HTTP, Git, OCI) are skipped. Errors are collected from every section before the command returns, so every issue surfaces in one pass.

**Usage:** `wash config validate [OPTIONS]`

###### **Options:**

* `--file <FILE>` - Validate a specific config file instead of the merged project config
* `-l`, `--log-level <LOG_LEVEL>` — Set the log level (`trace`, `debug`, `info`, `warn`, `error`) [default: `info`]
* `--non-interactive` - Run in non-interactive mode (skip terminal checks for host exec). Automatically enabled when stdin is not a TTY
* `-o`, `--output <OUTPUT_FORMAT>` — Specify output format (`text` or `json`) [default: `text`]
* `--user-config <USER_CONFIG>` - Path to user configuration file.
* `--verbose` - Enable verbose output
* `-h`, `--help` - Print help

## `wash host`

Run a cluster-connected wasmCloud host ([washlet](../runtime/washlet.mdx)) that joins the operator mesh via NATS.

**Usage:** `wash host [OPTIONS]`

###### **Options:**

* `--allow-insecure-registries` - Allow insecure OCI registries
* `--core-instances <CORE_INSTANCES>` - Instance slots in wasmtime's pooling allocator (`WASH_CORE_INSTANCES`; since 2.8.0) [default: unset, wasmtime's own 1000]
* `--data-nats-url <DATA_NATS_URL>` - NATS URL for data plane communications [default: `nats://localhost:4222`]
* `--default-heap-memory <SIZE>` - Ceiling on any single guest linear memory (`WASH_DEFAULT_HEAP_MEMORY`; since 2.8.0) [default: unset, wasmtime's own 4 GiB]
* `--drain-delay <DURATION>` - How long the host keeps serving after a shutdown signal, with readiness already failing, before it stops (`WASH_DRAIN_DELAY`; since 2.9.0) [default: `0s`; the Helm chart sets `5s`]
* `--guest-memory-mode <MODE>` - `count` records what enforcement would refuse; `enforce` refuses guest memory growth past the budget (`WASH_GUEST_MEMORY_MODE`; since 2.9.0) [default: `count`]
* `--host-group <HOST_GROUP>` - The host group label to assign to the host [default: `default`]
* `--host-name <HOST_NAME>` - The host name to assign to the host
* `--http-addr <HTTP_ADDR>` - The address on which the HTTP server will listen
* `--max-concurrent-starts <N>` - Workload starts (image pull plus compile) the host admits at once (`WASH_MAX_CONCURRENT_STARTS`; since 2.9.0) [default: CPUs minus one, clamped between 1 and 4]
* `--max-guest-memory <SIZE>` - Guest memory budget across every workload (`WASH_HOST_MAX_GUEST_MEMORY`; since 2.8.0) [default: three quarters of the cgroup or physical memory limit]
* `--max-http-ingress-connections <N>` - Connections the host's HTTP listener holds open; past the ceiling, connections are accepted and immediately closed (`WASH_MAX_HTTP_INGRESS_CONNECTIONS`; since 2.9.0) [default: a quarter of the descriptor limit, floor 256]
* `--nats-connect-timeout <DURATION>` - How long a starting host waits for NATS before failing (flag only, no environment variable; since 2.9.0) [default: `0s`; the Helm chart sets `60s`]
* `--probe-addr <ADDR>` - Serve `/livez` and `/readyz` health endpoints on this address (`WASH_PROBE_ADDR`; since 2.9.0) [default: disabled; the Helm chart serves probes on port 8081]
* `-l`, `--log-level <LOG_LEVEL>` — Set the log level (`trace`, `debug`, `info`, `warn`, `error`) [default: `info`]
* `--non-interactive` - Run in non-interactive mode (skip terminal checks for host exec). Automatically enabled when stdin is not a TTY
* `-o`, `--output <OUTPUT_FORMAT>` — Specify output format (`text` or `json`) [default: `text`]
* `--registry-pull-timeout <REGISTRY_PULL_TIMEOUT>` - Timeout for pulling artifacts from OCI registries [default: `30s`]
* `--scheduler-nats-url <SCHEDULER_NATS_URL>` - NATS URL for control plane communications [default: `nats://localhost:4222`]
* `--user-config <USER_CONFIG>` - Path to user configuration file.
* `--verbose` - Enable verbose output
* `--wasi-webgpu` - Enable WASI WebGPU support
* `--wasm-proposal <NAME>` - Enable a top-level Wasm proposal on the engine. Comma-separated and repeatable. Recognized values: `component-model-async`, `gc`, `exception-handling`, `wide-arithmetic`, `threads`, `tail-call`. Also readable from `WASH_WASM_PROPOSALS` (since 2.5.0)
* `--wasmcloud-nats-url <URL>` - Default NATS address for the `wasmcloud:nats` plugin's per-workload connections (`WASH_WASMCLOUD_NATS_URL`; since 2.9.0) [default: the data NATS URL]
* `-h`, `--help` - Print help
